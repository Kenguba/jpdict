# 2026-10-23 悬浮圆点窗口同步验证

## 根因与范围

上一版使用请求后的浮球坐标计算准星，但圆点仍画在独立全屏窗口中。实际拖动录屏中，球心 `(492,1170)`、圆点 `(518,1038)`，横向错开 26px；另一轮出现 48px，停稳后又对齐。两个窗口的位置提交与画布刷新没有共同的父窗口。两者已启用硬件加速，追加加速标志不能解决该问题。

本次仅将原圆点绘制移入当前可见浮球的 `TYPE_APPLICATION_PANEL` 附属窗口，原全屏层继续负责高亮和提示。复用原准星坐标、颜色、140ms 显隐和 OCR 状态；浮球本体持续挂载，代理切换时重新绑定。窗口注册使用现有 `getParent()` 判断方式，覆盖“已添加但尚未完成首帧”的快速取消/重入情况。

相对 `d8f33bf`：`OcrPickupController.java` 净增 1832 B，`FloatingService.java` 净增 64 B，生产代码合计 **1896 B**，低于用户单独批准的 **2048 B**。测试和文档另计，没有修改用户数据、词库、SAF、签名或版本分配逻辑。

## 实测

独立 QA 包、只读 Android API 37.2 arm64 模拟器，1080×2220、密度 2.75：

- 原浮球 → 代理 → 原浮球，连续移动中直接测量屏幕像素，24/24 个采样的水平差均为 **0px**；上侧 **−132px**、下侧 **+132px**，即 **±48dp**。
- 淡出期间重入、代理移除后立即重新绑定、取消和关闭均无残留窗口；圆点不可触摸、不取得键盘焦点。
- 真实窗口交互 745 条断言、截图 worker 59 条、选词回归 83 条通过；包含 24/44/100dp 浮球、不同按压位置、屏幕边界和上下切换滞回。
- 控制器 218 条、语言 163 条、真实模型 95 条通过；圆点实际 View 绘制在字母中心及间隙后仍可识别 `first`。
- 真实输入 → MediaProjection → 内置模型 → 查词小窗 → Back 连续 **20/20** 次通过，文本均精确匹配；覆盖英语、中文、日文和句子，保留同一服务/共享会话，包含延迟到达的旧停止通知。
- 手势规则 120 条、浮球配置 126 项、搜索状态及输入组合检查通过。三 ARM 变体 Lint 均为 0 errors / 110 warnings，QA 主包和测试包构建通过。

对抗式检查抓到了首帧前重复挂载的边界，已在原挂载条件修正后通过完整回归。早期像素测试受到测试底板透明度及绿色电池图标干扰，已校准底板与颜色筛选；首次真实往返测试因人工响应系统授权超时，及时授权后完整通过。上述失败没有计入通过结果。
