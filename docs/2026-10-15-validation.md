# 2026-10-15：欧路笔记、OCR 拖拽与后台导入验证

## 截图问题与修复

本机 `/Users/ken/Documents/japanese/日语单词总汇/` 中有 `日语单词总汇.mdx` 和词条脚本 `workClick.js`。脚本通过 `fetch` 请求欧路笔记接口，并在 `Authorization` 请求头中传入词库自己的令牌。应用此前为隔离词库内容而关闭 WebView 网络加载，页面 CSP 也不允许外连，因此浏览器在请求发往欧路之前就返回通用的 `Failed to fetch`。此时服务端还没有机会检查令牌；换用有效令牌也不能绕过这层拦截。

现在由原生网络适配器只代理该脚本需要的 HTTPS 笔记 GET 请求与它的 CORS 预检。它只接受精确的主机、路径、查询字段和允许的语言；令牌只从词库发来的请求头读取，再传给上游请求，不拼进 URL 或诊断信息。请求不跟随重定向，并设有并发、时长和响应大小上限。脚本里固定版本的 Eruda 调试资源也改为原生校验 SHA-256 后返回。其他外部地址、方法和路径仍由 WebView 网络阻断策略拒绝。令牌保存在各词库独立的 WebView 本地存储中，没有复制或记录截图里的令牌。

两张令牌截图可见内容并不相同；验证没有使用任何截图令牌或真实账户请求。发布后若错误变为 HTTP 401，表示请求已经到达欧路但令牌无效或过期，此时再将词库令牌字段更新为有效值；若页面继续显示网络错误，可据错误状态区分连接故障与授权故障。HTTP 成功但没有笔记，也可能只是欧路账户中没有该词的笔记。

这个网络适配只负责 `workClick.js` 的可选欧路笔记。原词条中的 `japanese_get_word` 仍是空白占位容器；脚本不会生成日语词库缺少的基础释义，所以修复欧路连接不会自动补出完整日语正文。

## OCR 拖拽与选择

- 拖动准星时，位置停稳 150ms 才触发 OCR；超过触摸 slop 与准星移动容差会重置计时，小幅抖动不会反复重置。
- 拖动开始后，空心圆点准星持续显示。常态指向浮球上方；屏幕下沿剩余空间不足以容纳浮球高度、12dp 间距和 4dp 圆点半径时切到下方。回到上方需要再多出 24dp 空间，避免边缘来回闪烁。浮球会保留准星所需的边缘空间；切换方向时清空当前笔画，避免把两侧路径错误连成一次取词。
- 识别结果使用字符框与文字框。用户可将圆点在同一段文字上往返滑动以圈定任意子串，例如在识别结果 `father` 上从 `f` 滑至 `r` 再返回 `f`；精读步骤受已选范围约束，避免把用户圈出的子串扩展成整段。
- 长按浮球打开方向摇杆，选择英语、日语或混合模式后，语言写入持久化的全局 OCR 配置；主页输入框及悬浮搜索读取同一配置。

## 后台导入进度

授权悬浮窗后，词库后台操作的圆形进度泡泡会随应用新建的悬浮窗口重新提到最上层；没有悬浮授权时继续使用应用内进度界面和系统通知。导入过程中发送低打扰的进行中通知，完成或失败后替换为可提醒的结果通知，点击直接打开词库页查看结果。Android 13 及以上在用户发起导入时请求通知权限。
