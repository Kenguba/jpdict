# 搜索居中、首帧跳位与连续截图修复

## 根因与修改

用户录屏中第二次打开搜索时，在 540×1200 抽帧上，2.311 秒的书本中心约为 y=445、输入卡顶部约为 y=950；2.353 秒变为 y=214、y=489。键盘到 2.517 秒才开始出现。跳动发生在键盘动画之前：页面在 `onSizeChanged()` 才应用预留键盘高度，而子视图的第一次测量已经结束。现在在 `onMeasure()` 使用待测窗口尺寸，先应用预留空间与紧凑模式，再测量子视图。

书本只在 `body` 内居中，但下方的联想区始终预留 124dp，即使只有一行提示也占满四行。这使可见空白的中心与书本中心不一致。联想区现使用实际内容高度；提示前的空白归还 `body`，提示文字和输入卡仍保持原本位置。初始提示在第一次布局前建立，避免异步联想返回后额外改变空白高度。

Android 11+ 的 `onApplyWindowInsets` 提供动画目标状态，`onProgress` 提供动画中间状态。前者记录最终键盘高度，后者只更新实时可见状态，不覆盖预留记录；结束时再次确认。隐藏键盘继续保留空间。旧系统保持可见区域稳定后测量，并在隐藏时清掉待确认值，使快速显隐后下一次相同高度仍可重新测量。

Android 不提供尚未显示过的键盘高度或通用占屏比例；高度随输入法、当前编辑器和键盘状态变化。已有方向缓存可用于首帧布局，全新安装或更换键盘后仍需首次校准。参考 [WindowInsets](https://developer.android.com/reference/android/view/WindowInsets) 与 [IME 动画](https://developer.android.com/develop/ui/views/layout/sw-keyboard)。未新增依赖，未使用目标 vivo 不兼容的 WindowInsetsController 路径。

OCR 每次请求原先重新创建 ImageReader 并更换 VirtualDisplay Surface，随后约 660ms 收不到新帧就撤销共享。反复切换消费者会中断画面接收，静止画面或首帧延迟也会被误判成授权失效。现在同一共享会话持续消费图像，只保留一帧，三个 acquisition 槽给 acquireLatestImage 留出丢弃旧帧所需空间；同一 Handler 上复制图像，每次生成独立 Bitmap，duplicate/rewind 不改变保留图像的共享缓冲位置。静止画面可重复读取，画面更新替换旧帧，方向变化和停止时释放资源。首帧约两秒仍未到达时释放请求状态并提示重试；真实授权停止或显示失效仍走重新授权。

没有目标手机日志，不能认定截图通道问题是该手机 OCR 失效的唯一原因。既有模型取消隔离逻辑保持不变；SDK 永久不回调的情况仍不能通过直接回收它正在使用的 Bitmap 安全解决，本次没有引入无限重试或无限保留截图。

## 已执行验证

使用 API 37.2 模拟器和独立 `com.yuen.jpdict.centerocrqa`、`com.yuen.jpdict.captureprobeqa` 包；未覆盖原应用或用户词库。

- 搜索布局 45 条断言通过：首次布局之前预留、两种字号、真实空白区域居中、目标高度先于动画帧应用、中间帧不写缓存、重复显隐、短窗口紧凑布局与方向缓存。测试使用实际 Android View 的测量和布局；未挂载的合成 Insets 测试不能代替真实系统动画结束回调。原实现对空提示区域高度的回归断言失败。
- 修复后真实窗口录屏：540×1212 抽帧上，首个完整搜索页书本中心为 y=314，系统确认键盘后仅校准到 y=316；键盘实际出现和后续画面保持该位置。没有再出现原录屏中输入卡上跳约 461px 的过程。此录屏在最终收掉提示前 17dp 空白之前拍摄；最终调整只把这段空白归还居中区域，未改变键盘处理。
- 最终布局在真实搜索窗口核对 Gboard 展开与收起截图：书本、联想提示、输入卡和快捷入口位置保持一致，收起仅移除键盘；键盘再次展开后的输入框坐标也一致。
- OCR 平台 109 条、语言 174 条通过。新增真实 ImageReader/ImageWriter 的五帧、每帧两次读取，核对像素更新、独立 Bitmap、静态画面重复读取以及首帧超时后恢复。
- 真实 MediaProjection 一次系统授权，生产 `captureOnce` 路径连续十次取得 1080×2424 截图：前五次静态蓝屏，切换后五次红屏；全程复用同一个捕获通道、VirtualDisplay 与 Surface，没有再次授权。临时探针只检查截图，不把颜色探针当成 OCR 模型识别精度测试。
- 三 ABI Debug 构建和 Lint 通过：每项 0 errors / 116 warnings。APK 均低于 5 MiB；跟踪源码加本次文件远低于 35 MiB。
- 搜索状态与输入组合测试、OCR 29 条纯 Java 规则、浮球配置 126 条、词典 2,646 条及调度/缓存/远程策略测试通过。

目标 vivo/OriginOS、旧 Android 实机、该手机第三方输入法和实际 OCR 模型精度未实测。签名、正式版本号与发布 APK 由 main 推送触发的 GitHub Actions 校验。
