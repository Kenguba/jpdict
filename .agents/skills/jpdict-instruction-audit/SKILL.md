# JPDict Instruction Audit（严格只读）

## 目标与范围

按需检查实际可访问且适用于当前项目的全局/仓库/子目录 AGENTS.md、项目级和用户级 Skills、Agent 定义、config.toml 与相关 README。先确认文件存在、可读、何时生效；不遍历所有源码或历史文档，不推断不可访问的本地配置。

## 审计项目

- **过度干活**：强制全文读取或全量测试、重复调查、过度抽象、无收益 Agent 树、额外文档和流程。
- **指令冲突**：全局/项目、AGENTS/Skills/README、模型与 Agent 规则、权限及旧配置之间的矛盾或重复。
- **无意义等待**：非关键强制确认、重复等待、不必要停止、子 Agent 失败没有降级路径。

## 方法与输出

1. 仅按实际文件内容核定问题，使用可核实路径、行号和逐字原句。相同问题合并，潜在风险与已确认问题分开，不能捏造数字、模型能力或配置。
2. 已确认问题表列：严重程度｜类别｜文件及行号｜原句｜原因与影响｜最小修改建议｜项目约束影响。
3. 汇总已确认数量和优先级；需要时提供可直接复制的完整建议版本，保留 Karpathy 四原则的四列表格（原则、英文、核心要求、解决的问题）。
4. 给出基于实际可用模型与环境的单/多 Agent 任务划分，避免重复调查与等待，不强制硬编码型号或树。
5. 保留安全、权限、用户数据、OCR/词典兼容、35 MiB 源码与 30 MiB APK、签名及版本/发布约束。无法验证的事项明确说明。

## 权限

仅分析和建议：不修改文件、不提交/推送、不创建 PR、不部署、不中断或触发 CI、构建和 Release。建议不自动进入实施。
